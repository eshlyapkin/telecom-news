# DESIGN — языки публикации и подписки пользователей

Статус: **implemented** (M8, 2026-09-11). Решения пользователя: гибрид
«канал + личка бота», отдельные сообщения на каждый язык, ленивый кэшируемый
перевод, расширение источников вместе с ослаблением фильтра (D-012).
Реализация и отличия от первоначального предложения перечислены в конце
документа. Раздел «Что есть сейчас» описывает состояние **до** M8 и оставлен
как обоснование.

## 1. Что есть сейчас (проверено по коду)

| Место | Факт |
|---|---|
| `config.py` | `target_lang: str = "ru"` (`TELECOM_NEWS_TARGET_LANG`) — ровно один язык публикации |
| `processors/summarize.py` | `summarize(..., target_lang=...)` — одно саммари на статью за прогон |
| `cli.py` (`_cmd_process`) | саммари сохраняется в `llm_result` статьи (JSON) вместе с `summary_language` |
| `delivery/telegram.py` | `send_message(config.telegram_chat_id, format_post(article))` — один канал, без состояния пользователей |
| `delivery/telegram.py` (`format_post`) | подписи «Категория:»/«Язык:» захардкожены по-русски |
| весь репозиторий | нет ни `getUpdates`, ни webhook, ни таблицы пользователей — входящие сообщения бота не обрабатываются вообще |

Вывод: «выбор языка пользователем» — это не правка формата, а новая подсистема
(подписки + обработка команд + доставка в личку). Поэтому нужен отдельный
milestone, а не патч внутри M4.

## 2. Требование

1. При первом подключении пользователь выбирает язык (сейчас поддерживаются `ru`, `en`).
2. Язык можно сменить в любой момент — на будущие публикации, без спама старой историей.
3. Пользователь может выбрать **несколько языков одновременно** и получать одну и ту же
   новость на каждом выбранном языке.
4. Каналы (публичные публикации) не должны сломаться: текущая доставка в `TELEGRAM_CHAT_ID`
   продолжает работать.

## 3. Варианты доставки

### Вариант A. Каналы по языкам
Один канал на язык: `TELEGRAM_CHAT_ID_RU`, `TELEGRAM_CHAT_ID_EN`; каждый пост уходит
в оба. Пользователь «выбирает язык» тем, на какой канал подписался. Возможен и
промежуточный случай: **оба языка в один канал** (два сообщения подряд) — тогда
«одновременно на двух языках» работает без отдельной подписки, но фильтровать языки
внутри канала всё равно нельзя.
- Плюсы: минимум кода, нет хранения пользователей, нет входящих команд.
- Минусы: **требование «выбрать несколько языков одновременно» не выполняется** в
  одном канале (в Telegram нет фильтра языка внутри канала), а «сменить язык в любой
  момент» сводится к подписке/отписке вручную. Дублирование контента в каналах.

### Вариант B. Рассылка в личку бота (подписки)
У бота `/start` → выбор языков → персональная доставка каждому подписчику.
- Плюсы: полностью закрывает требования 1–3; смена языка мгновенная; несколько языков —
  состояние одного пользователя; аудит, кто что получает.
- Минусы: новая подсистема (таблицы, обработка команд, долгоживущий процесс поллинга,
  лимиты Telegram на отправку в личку), бот должен быть публичным/доступным.

### Вариант C. Гибрид (рекомендуется)
Каналы остаются как сейчас (по одному языку на канал, язык из конфига), плюс
подписки в личке бота. Общий слой генерации контента на N языках используется обоими
каналами доставки.

**Рекомендация: C.** Он не ломает текущий сценарий (канал уже работает), даёт полный
ответ на требования 1–3 и не заставляет выбирать между каналом и личкой.

## 4. Модель данных (аддитивно, `CREATE TABLE IF NOT EXISTS`)

```sql
CREATE TABLE IF NOT EXISTS subscribers (
    chat_id      TEXT PRIMARY KEY,            -- Telegram chat id
    username     TEXT,
    ui_lang      TEXT NOT NULL DEFAULT 'ru',  -- язык интерфейса бота (кнопки/подсказки)
    status       TEXT NOT NULL DEFAULT 'active',  -- active | stopped | blocked
    created_at   TEXT NOT NULL,
    last_seen_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS subscriber_languages (
    chat_id  TEXT NOT NULL,
    lang     TEXT NOT NULL,                   -- 'ru' | 'en'; набор строк = выбор пользователя
    added_at TEXT NOT NULL,
    PRIMARY KEY (chat_id, lang)
);

CREATE TABLE IF NOT EXISTS renditions (       -- контент статьи на конкретном языке
    article_id INTEGER NOT NULL,
    lang       TEXT NOT NULL,
    title      TEXT NOT NULL DEFAULT '',
    summary    TEXT NOT NULL DEFAULT '',
    model      TEXT,
    created_at TEXT NOT NULL,
    PRIMARY KEY (article_id, lang)
);

CREATE TABLE IF NOT EXISTS deliveries (       -- журнал отправок: идемпотентность
    chat_id    TEXT NOT NULL,
    article_id INTEGER NOT NULL,
    lang       TEXT NOT NULL,
    message_id INTEGER,
    status     TEXT NOT NULL DEFAULT 'sent',  -- sent | failed | skipped
    attempts   INTEGER NOT NULL DEFAULT 0,
    last_error TEXT,
    sent_at    TEXT,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (chat_id, article_id, lang)
);

CREATE TABLE IF NOT EXISTS bot_state (        -- offset getUpdates и служебные флаги
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

Существующая таблица `articles` и `llm_result` не меняются (текущий `llm_result.summary`
остаётся рендером для языка канала — обратная совместимость).

## 5. UX бота

Роль: при `/start` — приветствие + inline-клавиатура:

```
🇷🇺 Русский          ✅
🇬🇧 English          ⬜
[ Готово ]
```

- callback-данные: `lang:toggle:ru`, `lang:toggle:en`, `lang:done`.
- Переключение сразу сохраняется в `subscriber_languages`; сообщение редактируется
  (Telegram `editMessageReplyMarkup`), «Готово» → подтверждение и подсказка `/help`.
- Если при первом `/start` ничего не выбрано — по умолчанию предлагается язык,
  подходящий `language_code` из Telegram (`ru*` → `ru`, иначе `en`), но **сохранение
  происходит только после нажатия кнопки** (осознанный выбор).
- `/language` (алиасы `/lang`, `/язык`) — та же клавиатура с текущим состоянием;
  работает в любой момент (требование 2).
- `/status` — «Вы получаете: 🇷🇺 Русский, 🇬🇧 English. Последняя доставка: …»
- `/stop` — пауза (`status='stopped'`), `/start` — возобновление.
- `/help` — список команд; неизвестный текст → та же подсказка.
- Тексты интерфейса выбираются по `ui_lang`; смена языка интерфейса — отдельная кнопка
  в `/help` (необязательно в первой версии).

Семантика смены языка (требование 2): изменение набора языков влияет **только на будущие
доставки**. Уже отправленное не переотправляется; новости, вышедшие между сменой языка,
не «доигрываются» — за это отвечает `deliveries` и окно свежести (см. §7).

## 6. Несколько языков у одного пользователя (требование 3)

`n` выбранных языков = `n` отдельных сообщений на одну новость (по одному на язык).
- Плюсы: не превышаем лимит 4096 символов, мобильная вёрстка читаемая, у каждого
  сообщения свой пост-футер (`Источник` / `Source`).
- Первое сообщение каждого языка получает флаг страны (🇷🇺 / 🇬🇧), чтобы не путаться,
  если новость пришла на двух языках подряд.
- Альтернатива «одно сообщение двумя блоками» отвергается как дефолт (смешение языков
  в одном сообщении хуже читается), но при желании вводится флагом настройки.

## 7. Конвейер контента на N языках

1. `relevance` считается один раз на статью (язык-независимый вердикт).
2. Языки-рендеры: `renditions` заполняются лениво — при первой необходимости языка
   (для канала — из конфига; для подписчиков — при планировании доставки).
   Один вызов LLM на (статья, язык), результат кэшируется в `renditions`.
   Это дешевле, чем заранее переводить на все языки.
3. Если рендер для языка не удалось получить (LM Studio недоступна/кривой ответ) —
   доставка для этого языка откладывается, `deliveries.status='failed'`,
   повтор в следующем цикле; статья не теряется.
4. Окно свежести: не отправлять статьи старше `SUBSCRIBER_MAX_AGE_HOURS` (по умолчанию 24).
   Защищает от «флуда историей» после простоя или новой подписки.
5. Лимиты: не более `SUBSCRIBER_MAX_PER_CYCLE` (по умолчанию 10) сообщений на
   пользователя за цикл и пауза ≈1 с между сообщениями в один чат (лимит Telegram —
   ~30 сообщений/с глобально, ~1/с на чат). Порядок — по возрастанию `article_id`.
6. Ошибка `403 Forbidden` (пользователь заблокировал бота) → `subscribers.status='blocked'`,
   больше не пытаться; прочие ошибки Telegram → повтор в следующем цикле (не более 3 попыток).

## 8. Где живёт обработчик команд

| Режим | Как работает | Плюсы/минусы |
|---|---|---|
| Долгоживущий `python -m telecom_news bot` (long polling, `timeout=25–30s`) | Мгновенная реакция на `/start`, `/language` | Нужен ещё один процесс: systemd в WSL или Task Scheduler «At logon» + `nohup` |
| Короткий поллинг внутри `run` (`getUpdates` с `timeout=0`) | Ничего дополнительно запускать не нужно | Ответ на команду приходит с задержкой до 15 минут — плохо для первого `/start` |
| Гибрид (рекомендуется) | `bot` — только команды; `run` (cron) — сбор, обработка, доставка подписчикам | Два процесса, но у каждого одна роль; доставка не зависит от того, жив ли поллер |

Offset `getUpdates` хранится в `bot_state`, поэтому перезапуск процесса не теряет и не
дублирует команды. Одновременный запуск двух поллеров запрещается блокировкой
(тот же приём, что `flock` в `scripts/run_pipeline.sh`).

## 9. План внедрения (предложение: milestone M8)

| Шаг | Содержание | Критерий готовности |
|---|---|---|
| M8.1 | Мультиязычный контент: `target_langs` в конфиге, `renditions`, `format_post(lang)` с подписями на языке поста, каналы по языкам (опционально) | Тест: одна статья → рендеры `ru` и `en`; повторный вызов не тратит LLM |
| M8.2 | Хранилище подписок + обработчики команд бота (`/start`, `/language`, `/status`, `/stop`, кнопки-переключатели) | Тесты на callback-данные и на смену языка; offset переживает перезапуск |
| M8.3 | Планировщик доставки: `plan_deliveries` (статья × подписчик × язык), окно свежести, лимиты, идемпотентность, ретраи, 403 | Тест: повторный прогон не отправляет то же сообщение дважды |
| M8.4 | Эксплуатация: `bot` как долгоживущий процесс, документация, `doctor`/`diagnose` знают про подписки и очередь доставки | Ручная проверка в Telegram; `diagnose` показывает подписчиков и размер очереди |

Явные non-goals M8: выбор тем/категорий, персональные фильтры, несколько ботов,
перевод через внешние API, ре-доставка истории по требованию (кроме `/latest N` как
отдельной задачи), учётные записи/биллинг.

## 10. Решения (закрыты 2026-09-11)

1. **Доставка:** гибрид C — канал(ы) остаются, подписки в личке добавляются.
2. **Несколько языков:** отдельное сообщение на каждый язык.
3. **Момент генерации:** лениво при первой доставке, с кэшем в `renditions`.
4. **Переводчик:** та же локальная LLM (LM Studio); внешние сервисы не подключаются.
5. **Объём публикаций:** расширять список источников и одновременно ослабить фильтр
   для узких лент (D-012).

## 11. Что реализовано и чем отличается от предложения

| Пункт предложения | Реализация |
|---|---|
| Выбор языка при подключении | `/start` сохраняет язык по локали Telegram (`ru*` → ru, иначе en) сразу, чтобы новости начали приходить без лишнего шага; клавиатура показывает оба языка и позволяет тут же изменить выбор |
| Смена языка в любой момент | `/language`, `/lang`, `/язык`; каждое нажатие кнопки применяется немедленно (без отдельного «сохранить») и меняет только будущие доставки |
| Несколько языков одновременно | набор строк в `subscriber_languages`; на каждую новость — по сообщению на язык, с флагом 🇷🇺/🇬🇧, если языков больше одного |
| Ленивый перевод | `processors/renditions.py::ensure_rendition` + таблица `renditions`; языки каналов генерируются в `process`, языки подписчиков — в `deliver` |
| Идемпотентность | таблица `deliveries` (ключ `chat_id, article_id, lang`) для каналов и подписчиков; `publish` не вызывает LLM и для старых строк (до M8) использует `llm_result.summary` |
| Долгоживущий поллер | команда `bot` (long polling, `--once` для запуска из шедулера), offset в `bot_state`, единственный экземпляр через `data/bot.lock` |
